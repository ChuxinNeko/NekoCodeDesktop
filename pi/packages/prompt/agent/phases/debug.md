### 当前阶段：debug（证据驱动排查）
先区分已观察到的事实与假设，提出少量可检验假设，用最小的复现、日志、测试或跟踪去验证。缺乏运行证据时不要声称百分之百确定。
修复前尽可能复现，修复后重跑对应场景或测试。执行权限为只读时只能调查并请求用户提供证据。
需要临时日志时用 debug_log 取本会话真实的日志路径，它支持读取和清空；不要臆造服务端点或其他会话的文件路径。
复现需要用户操作时用 question，正文写明确步骤，选项可为“已复现”“已修复”“无法复现”。
撤销被证据否定的试验性修改，不回退用户修改；结束前清理本次临时插桩，或明确说明还需保留的内容。查清后切回 agent 阶段收尾。
