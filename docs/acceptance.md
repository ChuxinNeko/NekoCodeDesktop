# 验收中心

会话顶部的“验收”入口打开验收中心，普通 PI、Fusion 和 ACP 会话共用同一界面。
可以选择轮次、筛选状态、查看命令退出码与输出节选、浏览器 URL 与视口，或复制 Markdown 报告。
“请求验收”和“请求重新验证”会发送一条明确的会话请求，由 Agent 检查当前代码并选择验证方式，不会直接执行历史命令。

## 证据来源

- 常见测试、构建、类型检查及 lint 命令自动列入检查。只有结构化退出码为 0 才能显示通过。
- 含分号、管道、重定向或混合操作的复合命令，即使最后退出码为 0，也可能掩盖前面的失败，按未验证处理；建议每次工具调用运行一条检查命令。
- `browser_check` 在真实顶层页面读取横向溢出、元素可见性、文本、启用状态及视口内位置，并返回断言结果。先通过 `browser_action` 交互，再检查结果。
- PI 的 `acceptance_check` 可登记待检查项，以及带原因的跳过、未验证项。通过或失败必须关联本轮实际验证工具的调用 ID；自定义验证命令也可以显式关联。
- Fusion 和辅助任务的命令、源码编辑和浏览器检查事件以会话元数据保存，供父会话验收中心重建。
- ACP 只使用外部 Agent 实际提供的证据。没有结构化退出码的完成状态显示“未验证”；不会从日志中的“pass”或模型回复猜测成功。

证据保存在原会话记录中，重新打开时重建，展示不依赖模型重新总结。
历史会话没有保存的执行元数据无法补造。成功打开页面或执行任意 JavaScript，不属于浏览器断言通过。

## 状态与范围

支持待检查、检查中、已通过、未通过、已跳过、未验证、需重新验证。
本会话或已上报的辅助任务在检查开始后编辑文件，或运行可能改变工作区的命令，会使旧通过/失败结果过期，包括跨轮次和并行执行的情况。
无法判断是否写入的命令按可能修改处理，因此过期检测有意保守。
中断或结束后仍未返回的检查显示未验证。

“已通过”只表示所列检查通过，不代表全部需求或完整视觉验收通过。
过期检测不监听用户在外部编辑器中的修改，也不能覆盖插件或外部 Agent 没有上报的操作。
文件列表来自观察到的文件编辑，不是完整 Git diff；命令可能修改其他文件。

为限制桌面和手机快照大小，界面保留最近 8 个轮次、总计最多 30 条检查和有界输出节选；完整历史与工具日志仍留在原会话中。
