# 模型能力自动识别

在设置 → 模型中点击“获取模型列表”或“重新获取”，会同时识别上下文窗口、单次输出 Token 上限和支持的思考等级。新建供应商时沿用现有的自动获取流程。

已启用模型列表支持多选、全选后“批量配置”。在弹窗中分别勾选需要统一设置的上下文窗口、单次输出上限或思考等级，未勾选的项保留各模型当前值；一次提交所选模型的全部修改。“全部恢复自动值”清除所选模型的手动限制和思考等级。切换供应商会清空选择，OAuth 模型仍沿用只读目录。

每项配置的优先级为：模型的手动覆盖 → 按模型 ID 匹配的 pi 内置目录 → 接口返回值 → 供应商默认值。同一 ID 在多个供应商里不一致时，优先采用与当前协议对应的官方供应商。上下文和输出上限仍须整项一致；思考等级保留每一家都支持的等级，因此各家都有的 `max` 不会因为 `off` 或 `low` 不一致而被丢掉。其余冲突字段不猜测。设置页列出供应商时就会套用这份目录，不必先重新获取。列表和配置弹窗会显示每项来源，悬停来源行可查看获取时间。配置中的“重置”清除手动覆盖，恢复自动值。

自动值与手动覆盖分开保存。已启用模型的能力缓存会持久化；本次获取后再添加的模型也会保存对应能力。刷新失败保留原缓存。切换接口地址或协议会清除旧接口的自动值，旧请求返回也不会覆盖新接口配置。成功获取后会重新注册运行时模型，使会话和设置页使用相同的有效值。

Claude 模型还会保存自适应思考模式及是否允许禁用思考，并在自定义供应商注册时传入请求兼容配置。已有配置即使尚未重新获取，也会从运行时已加载的同 ID Claude 目录继承这些协议要求；需要 adaptive 的模型不再发送旧式 budget，禁止关闭思考的模型不再发送 `thinking.type=disabled`。旧式模型继续使用 budget 模式。连接测试为 Claude 预留 2048 个输出 Token，避免自动思考耗尽原先的 8 Token 额度。

支持的接口元数据：

- OpenRouter：`context_length`、`top_provider.max_completion_tokens`。
- Claude：`max_input_tokens`、`max_tokens`，以及 `capabilities.thinking` 和 `capabilities.effort` 明确提供的自适应思考等级。
- 兼容接口：`contextWindow`、`maxTokens`、`max_output_tokens`、`max_tokens`，以及明确提供的 `thinking_levels` / `supported_thinking_levels`。

只有“支持推理”的布尔值或参数名称不能确定完整等级集合，不会由此猜测 xhigh、max。内置目录只做准确 ID 匹配。已知官方域名只查该供应商的目录。中转若有更紧的限制，用手动覆盖。

能力获取只请求模型元数据，不发送聊天探测。内置目录按需加载，不在应用启动时新增网络请求。对于不提供元数据且内置目录没有记录的模型，仍可手动设置。
